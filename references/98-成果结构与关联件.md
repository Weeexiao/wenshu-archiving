# 成果结构与关联件

## 输出形态

按用户提供的2025年档案室层级输出；根路径由用户指定，不绑定盘符或要求访问原示例。公开包只携带规则，不携带业务文件。

```text
2026年/
├─ 永久/
│  └─ 办公室（党委办公室、党委工作部）/
│     └─ 0001-关于某事项的通知/
│        ├─ 关于某事项的通知.pdf
│        ├─ 关于某事项的通知.ofd
│        ├─ 关于某事项的通知.mhtml
│        ├─ 附件1：工作方案.docx
│        ├─ 附件2：人员名单.xlsx
│        └─ 审批单/
│           └─ 审批记录.pdf
├─ 长期/
│  └─ 部门全称/0001-某事项材料/
└─ 短期/
   └─ 部门全称/0001-某事项材料/
```

三表目录放在指定成果位置；过程清单、核对说明和日志另存过程资料，不混入单元。空期限无须造空单元。既有成果只作结构参考，不自动迁移、改名或再次归档。

## 保持关联

主文及附件、签批/审批单、对应请示与批复、同一检查事项整改与复查、同一次会议成套材料，确认关联后进入同一单元。关联依据应为原文引用、文号对应、审批流程或能核实的业务链；仅题名相似、同一月份或同一部门不足以合并。

一个单元一个档号。三表中可列多条记录共用档号，各条题名、责任者、日期据实填写，单元题名概括整个事项。统计单元数计一次，记录数按实际行；不能把多格式副本机械当多条业务记录。

保留同一文件的不同格式、正式版及有归档价值的签批稿，不把OFD/MHTML改扩展名为PDF。正文附件可平铺，已有“审批单”等子目录保留。不同来源同名异内容时按“1-请示”“2-批复”等子目录区分，保留原名和来源映射，不覆盖或只留一份。

按适用制度确定单元统一期限；关联材料建议期限不一致时记录依据并判断成套保管要求，通常按其中最高期限保存，不能为分期限拆散事项。跨年度按办结及适用规则判断，不清楚时单列核对。

## 执行计划

plan.csv可使用“关联组”和“子目录”。关联组是本次工作内稳定的事项标识，不是档号。示例：

```csv
期限,部门,序号,题名,源路径,关联组,子目录
长期,办公室（党委办公室、党委工作部）,0001,某事项请示批复材料,D:/待归档/请示原件,事项001,1-请示
长期,办公室（党委办公室、党委工作部）,0001,某事项请示批复材料,D:/待归档/批复原件,事项001,2-批复
长期,办公室（党委办公室、党委工作部）,0001,某事项请示批复材料,D:/待归档/审批单,事项001,审批单
```

完整且未混装的单元源文件夹可整夹复制并保留相对层级；来源分散时多行指向同一目标。目录列有但正文未收到的列缺件，不造空文件。

交付前逐组核对计划与实际文件：已收到且应归档的关联文件都在目标单元，无跨单元拆分、同名覆盖；目录各行档号定位同一文件夹。脚本只检查计划内声明的关联组一致性，不能自动找出漏填计划的关联文件，Agent仍须核对正文及附件清单。
